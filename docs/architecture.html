System Architecture

Factory Inventory Management System

A workshop-grade full-stack demo: a Vue 3 single-page application served by Vite, a FastAPI backend, and a small JSON-file data layer loaded into memory at startup.

Frontend localhost:3000 Backend localhost:8001 API docs /docs No database — in-memory mock data

01 System Architecture

Three logical tiers. The browser talks to a Vite-served SPA, which calls a FastAPI service via JSON over HTTP. The service loads mock data from disk once at boot and serves it from memory.

03 Data Flow

One representative read path — a user changes the Warehouse filter on the Dashboard and the page re-renders.

1

User interaction

User changes a select in the global FilterBar (warehouse / category / status / month).

components/FilterBar.vue
2

Shared reactive state updates

FilterBar mutates refs that live in the useFilters composable. Any view that consumes those refs reacts.

composables/useFilters.js
3

View triggers a fetch

The active view (Dashboard / Inventory / Orders / …) watches the filters and calls the centralized API module, passing the current filter values.

views/*.vue → api.js
4

HTTP request

The api module serializes filters via URLSearchParams (skipping any value equal to 'all') and issues an axios GET to http://localhost:8001/api/….

GET /api/dashboard/summary?warehouse=…
5

Server filters in memory

FastAPI parses query params, runs apply_filters() and filter_by_month() over the in-memory lists, computes aggregates where the route requires it.

server/main.py
6

Pydantic validates and serializes

Response is validated against the route's response_model and returned as JSON.

InventoryItem · Order · …
7

View assigns to refs

The view assigns the JSON to its local refs (allOrders, inventoryItems, summary fields).

views/*.vue
8

Computed properties + template re-render

Derived data (KPIs, chart series, table rows) recomputes from the refs and Vue patches the DOM. SVG charts re-draw.

browser DOM
